五、新候选确实在补原始 scope，但现在应该停止继续加名单
这一轮终于不只在比较不同 Beta 估计器了。
结构多样性与恢复：已经有具体、可计算的定义
新增两个候选分别是：
**同一道任务四条轨迹的函数调用序列差异。**代码用函数名序列的归一化编辑距离衡量，因此它是调用路径的变化，不等于语义多样性、任务多样性或正确解法多样性。
**显式工具错误之后，在同一用户轮次出现非错误调用并最终有效完成的比例。**它反映一种可观察的恢复结构，但仍与成功率相关，也不能证明后续调用在因果上完成了修复。
这比给相同成功率信号换一种平滑方式更接近原始问题。两者使用已有 4B feature 轨迹，已经单独拟合并冻结；由于定义时 4B 目标结果已开放，4B 上的表现只能作为探索，未来 8B 验证才是新增的前瞻证据。
信息与兼容性：也有有限实现，但命名不能超过测量对象
另外两个模型条件代理是：
**工具反馈内容被遮蔽前后，后续模型 token 的似然变化；以及当前模型对固定 4B 参考经验的平均 token 似然。**它们分别尝试捕捉反馈依赖和对参考经验的相容程度。代码确实计算这些具体量，并没有直接估计一般意义的互信息。
这个设计可以做，但要守住两个解释限制：对遮蔽输入敏感，不等于反馈对实际任务成功有同等因果价值；对旧 4B 轨迹给出高似然，也不自动等于这些轨迹更值得训练。
其计划是固定的 32 个只做前向评分的作业，不是再训练 32 个模型；虽然没有新增生成 token，仍有非零推理计算成本，上限已单列。
