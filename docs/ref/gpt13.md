四、我对预测代码有一个重要的解释提醒：预测成功不等于“高分经验更好”
我读了 bfcl_transfer_predictor.py。当前是按既定契约，对每个信号分别拟合带截距的一元 ridge；只用拟合组计算标准化，并且斜率没有被限制为正数。这是一个合理的预测实现。
但它有一个需要在结果解释中守住的区别：
\[
\boxed{\text{一个信号包含预测信息}}
\neq
\boxed{\text{这个信号越大，经验越值得学}}.
\]
例如，假设最后拟合出来的是：
局部混合奖励机会越高，迁移收益反而越低。

只要这个负向关系在留出来源上成立，ridge 也可能比均值基线预测得更准。那支持的是条件性的负向预测关系，不是“优先选择高可学习性来源”得到了支持。
**因此，最终不能只展示一个 MSE 降低。还要展示斜率方向、各来源的预测／实测值，以及方向在重复或阶段之间是否保持。**这些信息模型本来就会输出，不需要新增 GPU 实验，也不需要改变当前冻结拟合规则。
另一方面，如果固定 ridge 没有胜过均值基线，结论也是“这个预设预测器在这些条件下没有改善预测”，不是直接否定整个可学习性假说。
这正是测量论文与“方法涨点论文”的区别：我们需要解释关系，而不是只决定谁赢。
五、58 对比较广度的补充是有用的，但还不等于恢复了原来全部 H1–H7
你上一轮问“是不是又变窄了”，这次 53 已经明确承认：当前主要围绕可学习性，尚未覆盖信息、恢复结构、兼容性等原始候选。这一点没有再用“长期目标没变”含糊带过。
新增的 58 给出了一个具体而不昂贵的扩展：来源组的原始成功率。
它与混合奖励机会确实不是同一个量。现有 feature 数据里就有这样的配对：
来源组	任务级 Beta 混合概率均值	成功率
MessageAPI＋TravelAPI	0.477513	7/24
TradingBot	0.477513	17/24


混合概率对成功／失败方向是对称的，所以两组可以得到相同的机会分数，但成功率不同。这个配对来自已采的 feature 数据，不需要额外调用模型。
这使我们至少能进一步区分：
更经常成功的经验来源是否值得学？
更容易产生成功／失败差异的经验来源是否值得学？

但文档也正确说明了：这仍然是来源组成功率对 RL 收益的预测，不是“直接用成功轨迹训练优于失败轨迹”的因果实验，更不是已经覆盖了信息量或恢复结构。
我赞成它作为独立登记的后续比较，不赞成现在把它临时塞进已经冻结的主结果，或者等看到全部 \(G/V\) 后再把表现最好的信号改称主方法。
六、目前有两个范围限制，结果出来时尤其要记住
预算阈值相同，不是实际剂量完全相同
当前按完整组停止，所以某些分支会有明显超额。例如 group06 repeat 0 实际用了 83,198 token，比名义 65,536 多约 27%。它符合冻结规则，不是违规；但不能在主表里统一写成“严格等 token”。
**本轮保持原协议完成，报告实际成本和末组占比即可。**不要事后裁掉轨迹，也不要简单把收益除以 token，就认为所有剂量差异都被控制干净了。
这批没有对应的新 ID 主面板
当前主要目标是组合迁移收益。53 已明确指出：不能把旧配方的 ID 结果，拼到新配方的迁移结果旁边，得出“ID 涨了但迁移没涨”的结论。
这不妨碍本轮回答“来源组信号能否预测迁移收益”。只是将来要提出 ID–OOD gap，需要同一批训练检查点的相应评测，不能借历史表格补出那一半证据。
