一、这次完整结果是什么？
固定同一个 Qwen3-4B 起点，对全部 87 道训练题、16 个来源组进行探测。每题先采四条轨迹用于形成预测，再采独立的四条用于验证，共 696 条轨迹。没有参数更新，没有使用保留的迁移测试题。
预测目标很具体：
下一组同题四条 rollout，是否会同时出现成功和失败？

不是预测任务平均成功率，更不是预测最终迁移能力。
冻结的主要结果如下，Brier 是概率预测的均方误差，越低越好：
预测方式	来源组宏平均 Brier
逐任务估计，再汇总：任务级 Beta	0.235364
先合并组合内所有奖励：当前组合 Beta	0.341164
旧历史组合 Beta	0.285969
当前组合平均成功率直接代入公式	0.356653
不看探测数据的固定 Beta 先验	0.281472


**主对照差为 −0.105799，相对当前组合 Beta 的误差降低约 31.0%。**16 个来源组中，任务级方法在 11 组更好、4 组更差、1 组持平。我复算了各组结果，与汇总一致；这不是“准确率提升 31 个百分点”，也没有据此建立总体显著性结论。
这次比此前 AUC 的回顾性分析更扎实，原因在于：**预测规则提前确定，形成预测后再获得验证奖励，没有用同一批四条轨迹既构造特征又验证自己。**评分代码和审计代码也确实区分了两批数据、预测文件哈希及封存时间。
二、我们之前举的极端例子，现在真的出现了一个对应样例
我专门查看了 MathAPI＋TravelAPI 的原始记录：
任务	用于形成预测的四次结果	独立验证的四次结果
multi_turn_base_157	[0,0,0,0]	[0,0,0,0]
multi_turn_base_161	[1,1,1,1]	[1,1,1,1]


两批都完整结束，没有靠截断形成这组差异。
如果把形成预测的八条奖励混起来：
\[
\bar p=0.5.
\]
于是组合级 Frontier 会认为这是最典型的“中间难度”；直接代入四次混合奖励概率，得到：
\[
1-\bar p^4-(1-\bar p)^4=0.875.
\]
但实际验证中，两道题各自都没有产生混合奖励。
这正好展示了我们想区分的两件事：
同一道任务有时会、有时不会；
一组任务里有些会、有些不会。

它们的组合平均成功率可以相同，但对“选一道题采四条，能否获得组内奖励差异”的意义不同。
当然，有限次数的全零／全一不证明真实成功概率严格等于 0／1。这个样例支持的是聚合可能掩盖任务内结构，不是已经证明了两道任务的极限成功率。整个批次也有四个来源组反而是组合级方法更好，不能只展示这个漂亮例子。
这一点已经可以作为论文中一个有实测支撑的现象，而不必再把它仅仅叫作工程检查。
三、不过，任务级方法“更好”不等于“已经测准了”
48 对这一点说得很准确：
来源组宏平均	混合奖励概率／频率
当前组合 Beta 的平均预测	0.697646
任务级 Beta 的平均预测	0.531476
独立验证的实际混合频率	0.392640


**任务级方法降低了高估，但仍然整体高估。**按任务数直接计算则是 30/87；它与按来源组等权的 0.392640 使用不同权重，不能混用。
我补充两个不需要重跑的解释。
当前四样本 Beta 预测，本身只有三个不同取值
按代码中的 Beta(1,1) 先验和每题四次 feature 采样，四次中成功数为 \(K\) 时，下一组四次出现混合奖励的预测是：
Feature 中成功次数	混合奖励预测
0 或 4	0.4365
1 或 3	0.6825
2	0.7619


这是直接按现有公式计算的。**即使一题四次全失败，它仍然至少预测约 43.7% 的混合机会。**所以现在看到整体高估，并不一定是执行错误，也与小样本及固定先验的平滑有关。
再给误差量级一个参照
对二元标签，永远预测 0.5 的常数预测器，其 Brier 恒为：
\[
(0.5-y)^2=0.25.
\]
因此任务级方法的 0.2354 比这个参照低约 0.0146。这是我补充的数学参照，不是本轮预注册的主对照，也不是要求你事后替换主指标。
它提醒我们：
相对一个偏差较大的组合预测器，改善很明显；但相对简单的不使用信息的预测，剩余优势没有那么大。

**这不是要求现在调先验、再采一轮直到校准漂亮。**保留原结果和原定义，直接把剩余测量误差带入下一步迁移预测，才更有信息量。

44 已经补上完整 Qwen/LoRA Trainer.train() 的检查：四微批累计梯度、最终参数和完整 AdamW 与冻结的手动参考一致，修正后的 backward 除数在循环前后保持为 1。结合此前目标函数与恢复检查，不需要继续重复同类固定输入验收了。
新的 train_bfcl_source_group.py 也明确落实了：

- 使用单次归一化，并在实际微步检查；

五、47 终于把我们原来要检验的“预测”写具体了
这次不再只是“等结果出来看看有没有规律”，而是提前规定了：
**16 个来源组，12 个拟合、4 个留出。**同一来源组的所有训练 seed、评测 seed和阶段数据绑定一侧，避免把相关重复拆开冒充新预测样本。
**主信号提前固定为任务级 Beta 混合概率。**每个候选信号分别拟合一个简单单变量 ridge，不搜索特征组合；主要比较它与“拟合组平均收益”基线在四个留出来源组上的预测误差。
**先封存实际预测，再打开留出分支的目标评测。**只冻结模型类别还不够，拟合参数、标准化和点预测也要有独立记录。
我尤其认可它区分了：
\[
G_g=\text{来源组训练后表现}-\text{同阶段起点表现},
\]
\[
V_g=G_g-G_{\rm Uniform}.
\]
同一阶段里共享一个 Uniform 参照，减去同一常数不会改变来源组排序，**所以 G、V 的相同排序结果不能算成两次独立验证。**但两者仍应同时报告：预测得准、确实变强、优于普通分配，是三个不同问题。
**这套结构已经对齐最初的 measurement scope。**不过四个留出来源组仍然很少，适合做有限条件的预测检验，不应包装成普适经验规律。
下一步最关键的不是再让局部预测误差下降一点，而是直接检验：
\[
\boxed{
\text{局部奖励机会预测更准}
\quad\stackrel{?}{\Longrightarrow}\quad
\text{来源组迁移收益预测更准}
}
\]
两边可能一致，也可能不一致。不要预先把第一边的正结果，当成第二边也会成功的保证。
