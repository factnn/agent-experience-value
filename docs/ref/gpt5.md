Scope 对齐与研究证据链：从在线经验分配回到可迁移能力
日期：2026-10-08
项目：Agent Experience Value
文档性质：研究方向对齐与后续实验建议，不是实验结果，也不是已经冻结的预注册。
讨论对应快照：608848d97d5242f7ca416cd02b135e210ea109a5。 本文不追踪此快照之后的运行状态，不修改正在执行的 pilot 协议。
核心决定：保留大 scope，保留在线 RL 主线，保留现有工程资产；但不能把“Uniform vs. Frontier 跑通或涨点”，直接当作“什么经验产生可迁移能力”已经得到回答。
当前最需要补的不是更多长度校准，而是：候选经验价值信号 → 受控 RL 干预收益 → 明确隔离的迁移收益。

1. 我们最开始要做的，是什么问题？
最初的动机来自 data mixture 的类比：既然训练数据的数量、组成和分配会影响学习，那么 agent 在有限预算下接触哪些环境、工具与交互经验，是否也存在可测量、可预测、可利用的关系？
我们没有决定第一篇就解决所有配比、顺序和规模问题，而是把它收敛为：
What Makes Agent Experience Valuable?
哪些交互经验的属性，能够预测训练后在未见任务、工具或环境上的能力提升？

原始 01_scope.md 的重点是三个部分：实际训练干预、比较不同经验价值假说、检验关系是否随 learner 规模或训练阶段变化；提出新 selector 只是可选项。[R1]
因此，论文原本要讲的故事不是：
我设计了一个更好的 curriculum，它比随机采样高几个点。

而是：
人们用成功、难度、多样性、信息、恢复结构、能力匹配等信号判断什么经验值得学。我们把可实现的候选信号放到同一测量框架下，检查它们究竟预测了什么、在哪些条件下有效，以及是否真的预测可迁移的学习收益。

研究原则：在一个重要的大问题上走一小步，但这一步必须有清楚的证据与适用边界。 不为了躲开相关工作不断缩题，也不为了保住已有代码，把研究问题改成代码恰好能做的事情。
2. 当前方向没有完全偏离，但当前实验还不等于原来的论文
讨论对应的项目快照已经恢复在线 RL 主线，并启动单种子的 Uniform / Frontier 双臂工程 pilot。[R2] 该协议使用一个模型、六个训练实例、三个同任务族的新评测实例；每臂目标为 120,000 个全部生成的模型 token，另外有更新步数与运行时长的安全上限。[R3]
它与最初 scope 的对应关系如下：
原始研究要求	当前双臂 pilot 覆盖到哪里	仍然缺少什么
比较经验价值假说	难度／可学习性信号，对比均匀分配	至少一个机制不同的价值假说，以及信号校准
测量训练后收益	可以比较两个 RL 训练流程的结果	重复干预、实际预算和效果稳定性
测量迁移能力	相同工具和三个任务族下的新实例	明确留出的任务结构、组合或工具族
理解信号为什么有效	已记录奖励组、梯度、采样成本等	局部信号与真实迁移收益之间的证据
检验关系是否稳定	单一模型、单一初始化种子、小预算	至少一条 learner 变化轴，如早期／后期


关键区别：增加种子、增加训练步数，能够改善当前对照的精度，但不会自动把“一个采样策略是否有效”变成“经验价值的测量研究”。
即使 Frontier 最终稳定胜过 Uniform，直接支持的也只是：
在所测模型、算法、预算、环境和目标分布下，这个分配规则更有效。

它不自动支持“难度最能预测经验价值”，更不支持“我们发现了普适的经验规律”。
3. 正式保留与纠正的 scope
3.1 保留的大问题
What makes interactive experience valuable for learning agents?

有限经验预算应该花在哪里？哪些交互带来的收益能超出当前任务？这种价值如何随 learner 改变？这是长期研究动机，不是本文已经完成的结果。
3.2 第一篇的操作性问题
在在线 agent RL 中，哪些采样前可获得的经验价值信号，能够预测预算受控的训练干预对未见任务的收益？这种关系是否随训练阶段和迁移目标改变？

限定“采样前可获得”是为了明确当前实现研究的是经验获取与分配。成功率、覆盖度等信号可以来自过去的训练交互；获取这些历史信息的成本必须计入。
3.3 第一篇的定位
Measurement / empirical learning study，而不是以新 curriculum 为中心的方法论文。
Frontier 是一个有根据的候选基线，不是必须保住的创新。Uniform 是资源分配参照。最终是否提出新方法，由测量结果决定。
3.4 不再发生的替换
- 不用 SFT 结果替在线 RL 作可行性结论。
- 不用 reward 上涨替代迁移能力上涨。
- 不用非零梯度或参数变化替代能力收益。
- 不用新任务 ID、改联系人名字替代跨任务结构或跨环境迁移。
- 不用完整在线策略的总效果，直接归因于某一种轨迹属性本身。
4. 先区分三个研究对象，避免干预层级混在一起
对象	实际改变什么	可以回答什么
经验获取／任务分配	采样前选择哪些任务、环境，分配多少尝试	哪种获取规则更有效地使用交互预算
经验利用／轨迹选择	在已获得的轨迹中选什么、重放什么或怎样加权	哪种利用方式更好地使用已有经验
轨迹属性的独立作用	在可比条件下改变或匹配恢复、信息、结构等属性	该属性是否造成了效果变化


当前主线选第一层。 每个分支用自己的当前策略继续采样，而不是共用固定 teacher 轨迹冒充在线 RL。
因此，两臂接触的任务分布可以不同——这正是分配干预。之前的 within-task 方案适合研究第二层，不能机械地要求当前两臂最终接触完全相同的任务。
但第一层的正结果不直接证明第三层。例如一个分配规则同时改变任务难度、轨迹长度和状态覆盖，其效果是这套规则的总效果，不能未经额外控制就归因为“恢复经验更有价值”。
大 scope 可以涵盖三层；第一篇必须明确自己实际识别了哪一层。
5. 定义要测的量：不要把经验价值称为脱离条件的“真值”
5.1 完整起点，而不只是模型权重
把分叉起点记为 $z_t$，至少包括：模型参数、优化器状态、学习率调度、可用训练历史及任务池版本。分配器的初始化信息也必须明确。
从同一个权重加载不同优化器状态，不是同一个学习起点。若研究“训练阶段的总影响”，可以保留各阶段自己的优化器状态；若进一步声称差异来自模型能力本身，则需要额外控制，不能混为一谈。
设 $q$ 为任务分配规则，$b$ 为一段经验获取预算，$\omega$ 表示训练与采样随机性，$r$ 表示预先定义的评测分布。
5.2 相对未继续训练的收益
\[
G_{t,r}(q;b)
=
\mathbb E_{\omega}\left[
M_{\mathcal D_r}\bigl(\operatorname{RL}(z_t,q,b;\omega)\bigr)
-
M_{\mathcal D_r}(\pi_t)
\right].
\]
它回答：按该规则继续 RL，相比当前模型是进步、持平还是退化？
5.3 相对均匀分配的效果
\[
V_{t,r}(q;b)
=
\mathbb E_{\omega}\left[
M_{\mathcal D_r}\bigl(\operatorname{RL}(z_t,q,b;\omega)\bigr)
-
M_{\mathcal D_r}\bigl(\operatorname{RL}(z_t,q_{\mathrm{uniform}},b;\omega)\bigr)
\right].
\]
它回答：在可比预算下，这种经验获取规则相对均匀分配好多少？两分支可以采用预先约定的配对随机种子，但不能因此假设实际轨迹相同。
同时报告 $G$ 与 $V$。 比 Uniform 掉得少，不等于比未训练模型变强；反之，两个策略都进步，也不代表二者之间存在可靠差异。
这里的值始终以 learner、算法、奖励、预算、目标分布和随机性为条件。实验得到的是有不确定性的估计，不是单条 experience 的固有价值。
5.4 三种信号分开测
层次	示例	不能直接推出什么
当前任务效用	成功率、任务 reward	不直接推出长期学习收益
当前优化信号	混合奖励组比例、非零优势、梯度统计	不直接推出未见能力提升
训练后能力收益	固定 ID 与迁移评测上的 $G$、$V$	只支持实际测试范围内的结论


训练中的在线 reward 会受到采样分布影响。Frontier 和 Uniform 接触的任务不同，因此不能只比较两者在线训练 reward 的均值来判断“谁学得更多”。学习收益需要在共同、固定的评测分布上测量。
6. 最小研究闭环：恢复证据链，而不是恢复一张巨大实验清单
E0 — 当前双臂工程 pilot：继续完成，但限定角色
用途是确认任务分配真正进入在线训练，并查清实际成本、有效干预长度和新实例表现。当前协议明确只有同环境新实例评测，不承担跨工具或跨任务族迁移结论。[R3]
结果首先核对：共同 warmup 后两臂是否真的分开；分配阶段占了多少成本；选中任务的分布、奖励信号和更新发生了什么变化。之后才看评测分数。
分数相同不自动杀题，分数不同也不自动证明经验价值假说。 若分配阶段太短或实际暴露几乎相同，先判为该对照的识别能力有限。
不在运行中为了结果好看修改公式、长度、预算或奖励。后续新设计另立协议，不追认旧实验通过。
E1 — 价值校准：从共同 checkpoint 做短程 RL 分叉
这是相较当前 pilot 最需要补回的科学实验。
从一个共同学习状态 $z_t$ 出发，对若干预先定义的任务组或分配配置分别开展短程在线 RL。保持算法、奖励、提示、推理模式和预算口径一致，仅改变经验获取规则。每条分支使用其自身更新后的策略继续采样。
每个分支同时测共同 ID 新实例集和冻结的迁移集。得到干预收益后，再检验采样前记录的候选信号是否预测这些收益。
候选主对照先控制在三个：
规则	代表的价值假说	初始地位
Uniform	不根据价值信号偏置分配	参照
Frontier / learnability	偏向当前尚未稳定掌握的任务	已实现的候选基线
Coverage / diversity	偏向过去交互覆盖不足的任务结构或工具组合	待定义的不同假说


Coverage 不应简单等于“新名字多”或“任务 ID 多”。优先使用已有 benchmark 中可核验的工具、任务结构等信息；具体表示、评分和归一化须在正式比较前写清楚。若依赖模型标注，应验证标注质量并计入成本。
本表不是说三种策略的三个均值足够拟合规律。 要对多个任务组、分配配置或干预批次形成独立观测，并在未用于选择规则的干预上验证预测。低预算试跑可以更小，但不能由此宣称统一校准了所有经验信号。
信息量、恢复结构、兼容性等暂不强制进入第一轮。简单近似只能标为“受该假说启发的基线”，不能冒充对某篇原方法的完整复现。
E2 — 一个针对解释的控制，而不是把所有机制都扫一遍
若 E1 出现清楚差异，围绕最主要的替代解释补一个控制。例如：
- 怀疑收益只是更多非零优势组：检查奖励混合程度可比的经验配置是否仍有不同迁移收益。
- 怀疑 Coverage 只是在偏向更简单任务：在尽量可比的难度分层内比较结构覆盖。
- 怀疑只是多完成了更新步：以相同获取预算为主结果，另做固定更新量的辅助对照，并报告二者成本差。
- 怀疑只是接口输出变化：保留官方端到端指标，并单独做不改任务语义的格式诊断。
成本、更新量等也可能是分配策略作用的中介，而不是都要在主实验里消除的“错误”。 主实验估计总效果，辅助实验检验解释。不要要求同时严格匹配 token、轨迹数、更新步数、长度与 FLOPs，从而把干预本身消掉。
不能仅靠事后回归、特征相关性或归一化分数，就宣称识别了某种轨迹属性的因果作用。
E3 — 稳定性：先优先检查训练阶段
在成本可行时，选择同模型的早期与较成熟 checkpoint，重复最有信息量的分叉对照。checkpoint 的选择规则应基于训练预算或开发设置提前规定，不能根据最终测试排名挑选。
要检验的是：同一候选信号对 $V_{t,r}$ 的预测是否稳定，或发生何种有条件的排名改变。
不能把“一个阶段显著、另一个阶段不显著”直接当作阶段差异；应比较效果差、交互或排名不确定性本身。单个偶然反转不足以成为中心结论。
第一篇可先不做跨模型规模。未测就不 claim；这不会取消长期的大问题。
E4 — 持续分配验证：可选，但有明确目的
若短程干预找到可重复关系，再选择有限几个配置做持续在线训练，检验关系是否能改善真实预算分配。
短程边际收益不一定等于长期累计收益，因此不能默认 E1 中最好的选择始终最好。若 E4 做不了，论文必须把结论限定在所测干预长度与阶段，而不是假装已经解决长期 allocation。
7. Benchmark：使用已有基准，但“已有”不等于“当前小夹具已经足够”
不新增一个大 benchmark，不把 MessageAPI 工程任务改名包装成论文 benchmark。 当前协议中的六个训练实例与三个测试实例是同模拟器、同任务族的新 seed，最多支持实例泛化。[R3]
下一步应在已有、可执行且具备可信奖励的任务基准中选择一个主测试场。优先保留其标准划分；需要新子划分时，明确版本、任务清单和隔离规则，并称为基于该 benchmark 的研究划分，而非官方标准成绩。
本文不重新确认历史候选 benchmark 的可用性、许可或训练用途，也不把旧聊天里提到的名称直接写成已经选定。真正需要落地的是以下表格，而不是再列十个名字：
项目	正式实验前应记录的内容
主基准与版本	具体 release / commit、来源与使用条件
训练部分	可交互任务、工具范围、可见 reward 与状态
开发部分	调提示、长度、奖励实现和分配规则所用任务
ID 新实例评测	同类任务的新实例；不参与训练与分配
迁移评测	预先留出的结构、组合、任务族或工具族；说明哪个维度确实未见
奖励验收	正例、反例、重置、越权或副作用检查，以及已知局限
防重叠	不仅检查 ID，还检查模板、指令、初始状态与来源重合


最低的评测区分
ID 新实例： 检查是否在原任务分布上产生有用学习。
明确的迁移切分： 至少有一个预先说明的分布变化，例如训练未见的任务结构或工具组合。跨工具／跨环境是更强层级，不必第一轮全部做，但只有真正隔离后才能使用相应措辞。
接口或任务族的工具说明可以在测试时提供，但模型未见过哪些任务、训练没有使用哪些反馈，需要说清楚。“有工具文档”与“用过评测任务训练”不是同一件事。
已用于开发的 BFCL 题不能再包装成从未查看的最终测试。复用某套模拟器也不自动构成污染；关键是训练信息、测试任务和声明的迁移轴是否一致。
8. 信号、结果与统计单位：避免做出一张看起来漂亮但没有解释力的图
8.1 信号必须先于其要预测的收益
用于分配的特征只能取自当时可用的训练信息。若使用独立探测来估计成功率或覆盖度，两臂共享的信息和成本要明确。
不能用最终测试得分构造“经验价值”，再在同一个测试集上报告预测效果。开发任务用于规则选择，确认性评测用于检验冻结选择。
8.2 统计单位是独立训练干预
一条训练分支采到 100 条 rollout，不等于做了 100 次独立的参数更新干预实验。多个评测题也不能替代多个训练种子。
报告时区分：独立训练重复、不同任务组／分配配置、评测任务数、每题 rollout 数。共享起点或共享对照的分支存在相关性，分析中应按设计配对或分层处理。
8.3 相关性只能是其中一项证据
Spearman / Kendall 可以描述候选信号与干预收益的排序关系，但需要足够的独立条件以及不确定性估计。对小样本、窄分数范围或高噪声结果，不应过度解读相关系数。
有预测器时，优先问：它能否在未用于拟合的任务组、分配条件或阶段上选出更有价值的经验？而不是只在同一张表上拟合得很好。
8.4 共同评测比在线训练 reward 更重要
两个分配器可以通过改变所遇任务的难度改变训练 reward。因此主结果必须来自固定的共同评测集；在线 reward、混合奖励组、非零梯度、长度与更新次数作为过程量单列。
9. 预算纪律：既不偷省成本，也不设置无法满足的完美匹配
当前 pilot 的协议已经计入失败与丢弃 suffix，并将最终评测成本与训练获取成本分开，这一原则保留。[R3]
后续正式实验应明确：
- 主要预算是什么。 全部生成 token 可以是主口径，但它不等于严格相同 FLOPs、墙钟时间或费用；同时报告上下文／输入开销、环境调用与实际计算开销。
- 共同起点和 warmup 怎么算。 共享起点的构建成本与分支增量成本分列，不把分叉比较伪装成从零开始都一样便宜。
- 估值和探测也要付账。 不能给一个分配器免费的大量试探，再只比较其后续训练 token。
- 预算越界提前规定。 组级采样可能超过目标，报告真实超额；必要时比较共同预算附近的检查点，不能把超额很多的终点叫严格等预算。
- 训练与评测分账。 不让测试开销混入某一分配器的经验成本，也不让评测反馈回流训练。
固定获取预算下，各策略的更新数、轨迹数和任务覆盖可以不同；这些正是需要记录并解释的结果，而不是全部强行匹配掉。

12. 有限资源下怎么推进，避免又陷入无限准备
当前正在跑的实验
按已冻结协议完成并归档。除安全或确认的实现错误外，不根据中间效果修改它。分析任务暴露、有效分配阶段、预算和新实例结果；不把它扩写成整篇论文。
下一笔主要实验投入
先把一个已有主 benchmark 的训练／开发／ID／迁移清单落实，然后复用现有采样、奖励、mask、更新和记账代码，做短程分叉干预。
不是先加更多 prompt、context、harness 消融；也不是先移植全部七八种 proxy。优先形成：有限候选假说 + 可识别的干预差异 + 可靠迁移测量。
成本分层
先在一个 checkpoint 上检查三种候选规则是否产生可测的经验与收益差异，再将有信息量的对照扩到独立重复和第二训练阶段。具体分支数量和预算根据已测成本及预期可检测效应确定，未测前不承诺完整模型矩阵。
不要把每个短分支都当作需要训练到收敛的大模型项目；但预算短到没有有效分配或更新差异时，也不能据此得出“没有作用”。
明确停止追加的内容
不继续无限追求零触顶；不把 SFT 调参放回 RL 门槛；不重新搭通用 agent 框架；不扩成多环境生成平台；不先写一个复杂的新 score；不为迁就 venue 临时塞入无关视觉实验。
13. 怎样判断“值得继续”，而不是又制造一套任意 GO／NO-GO？
把三种判断分开：
工程可行性： 能否以承受得起的成本运行真实在线更新和分配？这是当前 pilot 的主要职责。
实验识别能力： 候选规则是否真正改变经验分布？有多少分配阶段？迁移测试是否足以看见关心的效果？识别不足，应调整实验，不应自动杀掉科学问题。
科学证据： 在识别成立后，哪个假说得到支持？效果能否重复？能否预测未参与调参的干预？这一层决定论文 claim。
结果小于噪声时，先区分“区间太宽，信息不足”和“区间足够窄，排除了有用大小的效果”。已有简单 proxy 若表现稳定，也不是必须杀题；需要判断进一步的校准、边界与预测是否提供了实质新信息。
相邻工作同样按证据判断：核对目标、控制、评测范围和可复现性。相同标题不占领整个问题；但单纯换个名称、环境或指标也不自动构成新贡献。
14. 论文故事的冻结版本
Working title
What Makes Agent Experience Valuable? Measuring Transfer in Online Agent RL
一段话的论文定位
在线 agent RL 的交互预算有限。不同经验分配规则依据成功率、可学习性或覆盖度等信号选择下一批任务，但这些信号与训练后的迁移收益之间不能直接画等号。本研究以同一 learner 起点和预算受控的在线 RL 干预为基础，比较一组明确的候选价值假说，分别测量固定 ID 与隔离迁移分布上的收益，并检验信号—收益关系是否随训练阶段改变。分配策略的涨点是证据之一；核心目标是建立可检验、可预测、有适用边界的经验价值关系，而不是再提出一个未经校准的评分器。
三项预期贡献，不预写结果
1. 干预式测量： 明确以 learner、算法、预算和目标分布为条件的经验获取收益及相对分配效果。
2. 候选假说校准： 比较有限而机制不同的价值信号，检验其对真实 ID／迁移干预收益的预测，而不是宣称全面评判所有经验方法。
3. 边界与稳定性： 通过训练阶段及明确迁移切分，识别关系在哪些条件下成立或不成立；没有跨规模证据就不宣称跨规模。
最终决定
保护研究问题，不保护 Frontier 这个具体方法。
当前双臂 pilot 是基础设施和基线，不是原 scope 的完整缩小版论文。
要回到原 scope，需要补上“价值信号 → 受控 RL 收益 → 隔离迁移收益”的证据链。做到这一点，可以在一个模型、一个成熟测试场和有限候选规则下给出有分量的、条件明确的结论；做不到，仅扩大 Uniform／Frontier 对照不会自动变成经验价值研究。

继续： 已冻结工程 pilot；现有 RL 与审计管线；已有 benchmark 优先；在线经验获取成本完整入账。
补回： 明确的迁移切分；一个机制不同的候选假说；共同学习状态的短程分叉干预；预先记录的信号与真实收益对应；有针对性的阶段复验。
