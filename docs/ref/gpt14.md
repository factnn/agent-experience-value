需要修正，而且现在就值得改。但不是把目标再缩小，而是把“研究要回答什么、执行端可以自主决定什么、做到什么程度算完成”分开写清楚。
这版 Goal 的大方向是对的：在线 RL、真实迁移收益、阶段依赖、不追求强行正结果，这些都应保留。**主要问题是，它把科学目标、已经过时的执行路线、大量过程要求和不够明确的完成条件混在了一段里。**我建议改 Objective，不改变任何正在执行或已经冻结的实验条件。
一、最需要改的四处
1. 补回“比较不同价值假说”，不能只保留规模、家族、环境的大 scope
现在这句话：
“保留规模、模型家族、环境外推的大 scope”

保留了外推广度，但遗漏了我们原来另一半雄心：比较机制不同的经验价值判断。
原始 scope 不只是多跑几个模型，而是比较成功、结构多样性、信息、恢复、兼容性、可学习性等不同答案，检验它们与实际迁移收益的关系。
因此，Goal 应明确：
任务级 Beta、组合级 Beta、历史 Frontier 等同类估计的比较，不能替代不同经验价值假说的比较。

这不意味着现在马上补齐 H1–H7，也不要求所有模型跑全矩阵。它要求执行端明确记录哪些假说已检验、哪些未检验，不能因为某条局部路线比较好做，就悄悄把它当成全部研究。
2. 删除已经过时的“先完成重复，再验收分叉”路线
你现在的 Objective 还写着：
“先完成当前训练/评测重复并解释方差，继而……实现并验收非零学习状态分叉……”

但重复实验、确定性完整状态分叉、归一化接入等已经有完成记录；当前依赖是收齐来源组训练，进入真实迁移评测和预测验证。
长期 Objective 不该继续把已完成工作写成未来必经路线。
我建议让它只保留稳定目标和原则；具体“现在还有多少分支、哪个队列停了、下一步执行哪个脚本”，放在已有的 experiments/NEXT.md 和协议中。这样不会每次进展后都需要重写 Goal，也减少反复回到旧验收的风险。
3. 把“自主推进”改成“围绕关键问题自主推进”，不是无限增加工作
现在：
“自主选择和执行最有信息量的下一实验”

方向不错，但需要加一个约束：
新增实验必须说明它要区分什么解释、不同结果会改变什么决定、为什么不能先用已有证据回答，以及预期成本。

否则，“最有信息量”很容易被执行成：发现一个小疑问，就新增一套检查、协议、日志和实验。
同样，**最多四卡只是并行上限，不是总资源预算。**我的建议是每个新科学批次都明确总预算与停止条件，在授权范围内自主执行，不需要逐条问 go；重大 scope 变更、超出资源授权或修改确认性判据，再交给你决定。
已经通过的必要验收应该可以收口。除非新证据使它失效，否则不能不断增加更严格的同类要求。
4. 完成条件必须对应“科学交付”，不能只是文件齐了，也不能永远不许完成
现在：
“只有证据包及对应审计完成才可标记 Goal complete”

是必要条件，但还不充分：一份局部代理校准报告也可以可复现、可审计，却没有回答原来的迁移问题。
反过来，“保留所有大 scope，单批结束都不算完成”，也可能让目标没有终点。
应当区分：
阶段性交付：当前冻结的研究问题和证据链完成，正、负或不确定结果都如实报告。
整个 Goal 完成：达到事前约定的研究交付范围，关键结论有相应证据；未覆盖部分明确列出，不能执行端自行缩减原目标后宣布全部完成。
OpenAI 官方也把 Goal 定义为有明确结果、验证依据、约束和阻塞处理的完成约定，而不是无限循环的“继续干”。研究任务尤其要区分已确认、部分支持、受阻和仍然不确定的结论。OpenAI Developers
二、我建议替换成这一版 Objective
下面保留自主性和大问题，同时把终点、边界与当前文件体系接上：
自主推进 /share/project/zpy/RL/agent_experience_project_20260928 的在线 RL 经验价值研究，在已授权范围内无需用户逐次输入 go。

【科学目标】
研究哪些交互经验能够带来训练后真实、可重复的迁移收益，哪些采样前可获得的信号能够预测这种价值，以及关系是否随 learner 阶段改变。区分当前任务成功、局部更新机会、实际参数更新、ID 收益与迁移收益；不得用混合奖励预测、非零梯度、训练 reward 或工程验收代替迁移结论。既不预设某种方法必须获胜，也不预设局部信号必然失效或必须出现排名反转。

保留原始 scope 中机制不同的价值假说：成功、多样性、信息、恢复结构、learner 兼容性、可学习性及适用时的梯度影响。允许按资源与证据聚焦，但必须明确哪些已检验、哪些未覆盖、为何暂缓；同类代理的多个估计器不能冒充广泛机制比较。规模、模型家族与环境外推按关键结论的实际需要选择，不要求全笛卡尔积，也不能无依据从长期目标中删除。

【当前执行与统筹关系】
以用户确认的研究方向、已冻结协议、experiments/SCOPE_REVIEW.md 和 experiments/NEXT.md 为依据；NEXT 中的状态必须与实际作业及原始结果核对，不能只信旧状态文本。优先完成已启动的来源组 RL 训练、固定迁移评测、事前预测封存和留出检验，不回到已完成的同类校准或验收。

自主完成已授权方案、必要的最小实现修复、结果分析及后续方案设计。收到用户转交的统筹意见时，结合原始证据判断采纳方式，区分必须修复、仅需限制解释、可留待后续三类；不因每次审阅都重构方案。重大研究终点变化、确认性判据修改或超出授权资源的扩展，应说明证据和取舍并请求决定，但不得把每个普通作业都变成新的 go 门槛。

【实验选择与防止偏航】
每个新增科学实验先说明：要区分的关键解释、各类结果如何改变研究判断、已有数据为何不足、实际成本与停止条件。优先补齐“采样前信号—受控 RL 干预—迁移收益—独立预测验证”的缺失证据，不以新脚本、协议、审计或提交数量衡量进展。

局部代理校准是解释工具，不是必须达到理想分数才能进入迁移实验的前置条件。已通过的工程验收仅在新证据表明相关假设失效时重开。不得为了得到正结果反复调先验、换任务、加 seed、改变预算或追求漂亮的学习曲线。

【证据与统计纪律】
保持运行中及已冻结对照的可解释性。适应性调整另行登记原因与版本；不得依据部分测试结果删臂、挑 seed、改主指标或选择阳性。按任务、来源组、训练重复、评测重复和共享祖先的实际依赖分析，不能把相关重复冒充独立条件。

分别报告相对共同起点的 G、相对 Uniform 的 V、预测误差、关系方向和不确定性；预测更准不等于高分来源更好，V>0 不等于 G>0。确认性留出标签在规定的预测封存之前不可访问。保留失败、负结果、缺失与重试；测量不足时明确“尚不能判定”，不能冒充无效证明。

【执行、记录与资源】
最多使用四张实际空闲 GPU，不占他人作业；优先本地模型、数据和已有环境，不新增付费 API。新批次登记总预算、时间/采样上限与停止条件；并行上限不等于无限总预算。探测、训练、评测、失败与重试成本分账，共享成本只计一次。

对实质实验结果、重要执行故障及研究决定维护 experiments/E###、索引、NEXT 和 scope 台账；常规心跳、重复读取和中间步骤使用机器日志，不新增无意义的审批层。记录区分机器事实、执行 agent 的分析、外部审阅、结论边界和下一决策，不把 agent 自审称为独立人类复核。发布可追溯的代码、配置与已完成证据，不覆盖旧结果。

在已有授权和系统允许执行时，利用现有监控接续已登记作业，等待不忙轮询。中断后按原 job 身份保留已完成结果，只接续未完成部分；区分控制准入、查询依赖和科学运行失败。遵守用户暂停/取消、系统状态和额度限制，不自行绕过或重置受限状态；受阻时报告确切障碍、保留状态及恢复所需条件，不假装仍在运行。

【交付与完成】
交付可复现研究证据包：明确研究问题与假说、协议与代码/版本、原始结果与检查点取得方式、实际训练干预和迁移评测、预测及留出验证、重复与不确定性、成本失败账本，以及逐项 claim–evidence 对照。

阶段性交付可以包含正、负或不确定结论，但局部代理改善、单个作业、单批队列结束或文件齐全不等于整个研究完成。达到事前约定的科学交付范围及对应审计后才可标记 Goal complete；未覆盖的重要原始目标必须明确保留，不能自行降级后宣称全部完成。预算或权限受阻时交付当前证据与未完成项，不把受阻当完成；也不为维持 Goal 活跃而无目的扩张实验。
