# How to Map the Microsoft Wireless Keyboard 1000 Flip3D Key on Linux

## Problem
The Flip3D key (with 3 windows icon) between Space/Alt Gr and Menu/Ctrl
doesn't generate X events in xev, making it impossible to remap normally.

## Solution
The key IS detected by the Linux kernel, but X doesn't have a mapping for it.
We need to:
1. Find the scancode using evtest (kernel level)
2. Create a udev/hwdb mapping to assign it a keycode
3. Then remap that keycode in X

## Step 1: Identify the keyboard device

Run evtest and select your keyboard:

sudo evtest


You'll see a list like:

/dev/input/event0: Power Button
/dev/input/event1: Microsoft Microsoft® 2.4GHz Transceiver v1.0
/dev/input/event2: ...


Select the keyboard device (usually event1 for MS keyboards).

## Step 2: Find the scancode

With evtest running, press the Flip3D key. You'll see output like:

Event: time 1234.567878, type 4 (EV_MSC), code 4 (MSC_SCAN), value 70073
Event: time 1234.567878, type 1 (EV_KEY), code 256 (BTN_0), value 1


The important values are:
- MSC_SCAN value (e.g., 70073) = the raw scancode
- EV_KEY code (e.g., 256) = the current unmapped keycode

For Microsoft keyboards, the Flip3D key scancode is typically: 0x70073

## Step 3: Create a hwdb mapping file

Create a file to map the scancode to a standard keycode:


sudo nano /etc/udev/hwdb.d/99-microsoft-keyboard.hwdb


Add this content:

# Microsoft Wireless Keyboard 1000 - Flip3D key
evdev:input:b0003v045Ep0745*  # Use your vid/pid from 'cat /proc/bus/input/devices'
 KEYBOARD_KEY_70073=prog1


Replace 70073 with your actual scancode from evtest.
Replace prog1 with any unused keycode (f20, f13, etc.)

## Step 4: Apply the changes


sudo udevadm hwdb --update
sudo udevadm trigger


Unplug and replug your keyboard, or reboot.

## Step 5: Verify and remap in X

Now run xev and press the key - it should be detected!
You'll see something like:

KeyRelease event, serial 34, synthetic NO, window 0x4c00001,
    root 0x15a, subw 0x0, time 123456, (123,456), root:(124,470),
    state 0x0, keycode 234 (keysym 0x1008ff19, XF86Launch1), same_screen YES


Now you can remap it using xmodmap:

xmodmap -e "keycode 234 = Super_L"


Or create a permanent xmodmap file:

echo "keycode 234 = Super_L" >> ~/.Xmodmap


## Alternative: Using setkeycodes (older method)

If hwdb doesn't work, try setkeycodes:

sudo setkeycodes 0x73 234  # Map scancode to keycode 234


Then verify with showkey:

sudo showkey -k


## Troubleshooting

- If dmesg shows nothing, the key might need a HID quirk
- Check /proc/bus/input/devices for your vid:pid
- Try different keycodes in hwdb (f20, prog1, prog2, etc.)
