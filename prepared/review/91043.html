# SmartPy Contract Issue Explanation

## The Problem
When you name an entry point `default`, it conflicts with Tezos's reserved `default` entry point
behavior. The `default` entry point is a special fallback that gets called when:
- No entry point is specified in a transaction
- The entry point name doesn't match any defined entry points

This causes issues with other entry points like `setDelegation`.

## The Solution
Rename the `default` entry point to something meaningful like `receive_rewards`, `deposit`,
or `getRewardsFromBaker`.

## How the Baker Can Send Rewards
The baker CAN send rewards to your contract by specifying the entry point name in their
transaction. Here's how:

### Using tezos-client:

tezos-client transfer 1000 from <baker_address> to <contract_address> --entrypoint "receive_rewards"


### Using Taquito (JS/TS):

const contract = await tezos.contract.at(contractAddress);
const operation = await contract.methods.receive_rewards().send({ amount: 1000000 });


### Using PyTezos:

contract = pytezos.contract(contract_address)
contract.receive_rewards().send(amount=1000000)


## Key Points
1. Bakers can call any entry point by name - they don't need a special `default` entry point
2. Your `receive_rewards` entry point just needs to accept tez (verify amount > 0 mutez)
3. The rewards will be added to your contract's balance
4. You can then add another entry point to withdraw rewards if needed

## Complete Working Contract
