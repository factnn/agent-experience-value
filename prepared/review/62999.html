LEVEL_TAGS used by Django's message framework is not updated when tests use @override_settings to change MESSAGE_TAGS at runtime. As a result, newly created messages may keep stale level_tag values (e.g., an empty string). The bug is that LEVEL_TAGS is computed at import time and never refreshed when MESSAGE_TAGS changes. The fix is to listen for Django's settings change events and recompute LEVEL_TAGS accordingly.
