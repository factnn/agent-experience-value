The error you're experiencing is a common issue with Tezos testnet activation. Here's what's happening:

**The Problem:**
The error `Invalid activation. The public key xxxXXXXXxxxxx does not match any commitment` means that the public key associated with your account "bob" doesn't match the public key in your activation JSON file.

**The Solution:**

1. **First, check what's in your activation file:**
   ```bash
   cat container:xxxXXXXXxxxxx.json
   ```
   Look for the `public_key` or `pkh` (public key hash) field.

2. **Import the account using the secret key from the JSON file:**
   ```bash
   ./carthagenet.sh client import secret key bob unencrypted:<secret_key_from_json>
   ```
   The secret key in the JSON file is typically under the `"secret"` field.

3. **Then activate the account:**
   ```bash
   ./carthagenet.sh client -A rpctest.tzbeta.net -P 443 -S activate account bob with "container:xxxXXXXXxxxxx.json"
   ```

**Alternative approach - activate directly without importing first:**
Some faucet files allow you to activate by specifying the public key hash directly:
```bash
./carthagenet.sh client -A rpctest.tzbeta.net -P 443 -S activate account <public_key_hash_from_json> with "container:xxxXXXXXxxxxx.json"
```

The key is to ensure the account name or public key hash you're using in the `activate account` command matches exactly what's in your JSON activation file.
